# 2단계 결과: 탄소 인지 작업 스케줄링 시뮬레이션

`scripts/05_stage2_report.py`가 `03_분석/stage2/` 산출물로 자동 생성한 문서다. 직접 고치지 말고 스크립트를 다시 돌린다.

- 주 결과 곡선: **보수적 하한(전력시장 거래량만)** (`market`)
- 전력거래소 5분 단위 비계량 태양광 파일이 아직 없어 '실제 전력망 기준' 곡선을 만들지 못했다. 파일을 넣고 다시 돌리면 주 결과가 그 곡선으로 바뀐다.
- 함께 계산한 곡선: 보수적 하한(전력시장 거래량만) (`market`), 비계량 태양광 월별 배수 가정 (`monthly`)
- 실험 일수: 349일 (2025-01-08 ~ 2025-12-23 시작일. 전주 예측(E)에 7일 전 값이, 주간 작업에 7일 뒤 값이 필요해서 앞뒤를 제외)
- 실험 방식: 같은 하루치 작업 세트(30개)가 매일 들어온다고 보고, 날짜마다 독립 실험으로 돌린 뒤 합산

## 핵심 발견

**결론: 마감 유연성이 절감을 결정한다.** 같은 스케줄러라도 작업을 얼마나 오래 미룰 수 있느냐에 따라 절감률이 크게 달라진다.

1. **헤드라인(C, 스케줄링만):** 현재 관행(새벽 2시 고정) 대비 연간 **9.1%** 절감, 마감 위반 0건 (보수적 하한(전력시장 거래량만)). 시장 밖 태양광을 월별 비율로 반영하면 약 13.9%(가정).
2. **당일 마감 작업만 보면 4.5%.** 8~14시 마감 안에서만 움직일 수 있고 슬롯 2개를 나눠 써서, 한낮을 다 쓰지 못한다.
3. **주말 이동이 절감의 대부분이다.** 평일 시작 실험에서 주간 작업의 주말 이동을 막으면 1.6%, 허용하면 10.7% (+9.1%p).
4. **현재 관행 대비(곡선 기준):** 심야 2시에서 한낮(10~14시)으로 옮기면 연간 7.6%, 봄 10.9%, 겨울 5.8%. 저녁에서 옮길 때(9.8%)보다 작다.
5. **마감 위반 0건은 에이징이 아니라 15분마다 수행하는 EDF 가능성 검사(schedulability test) 덕분이다.** 에이징 강도 γ는 절감률과 대기 시간의 균형만 조절한다(8장). 탄소만 쫓는 B는 3,400건 위반.
6. **예측의 한계:** 완전 정보 가정을 풀고 전주 같은 요일 값으로 예측하면(E) 절감률이 3.0%p 줄어든다 (9.1% → 6.2%).
7. **기다리는 시간:** 당일 작업의 완료 지연은 중앙값 8.0시간(A는 4.9시간), 주간 작업은 중앙값 108.2시간. 전체 평균 지연이 큰 것은 주간 작업이 주말을 기다리기 때문이다(2-1절).
8. **DVFS(D)는 모델 가정에 따라 22~49%** (정적 전력 비율 0.5~0.21), 근거 있는 기준값 0.33에서 37.2%. 6장 참고.

외부 연구와 비교: Wiesner et al.(Middleware '21)도 "shifting workloads whose results are not needed by the next working day can already reduce emissions by over 5 % across all regions", "shifting delay-tolerant workloads towards weekends can result in more than 20 % savings in most regions"라고 보고했다(references.md 4-4). 미룰 수 있는 기간이 길수록, 특히 주말까지 미룰 수 있을 때 절감이 커진다는 방향이 같다.

## 4. 평일 작업을 주말로 미루는 효과

평일에 시작한 실험 234일만 비교. C7은 주간 작업도 다음 날 14시까지만 미룰 수 있게 막은 C.

- A 대비 절감률: C7(주말 이동 없음) 1.6% → C(주말 이동 허용) 10.7%
- 주말 이동으로 늘어난 절감: **9.1%p** (작업 30개 전체 배출 기준)
- 주간 작업 6개만 보면 C7 대비 C가 15.9% 덜 배출
- C에서 주간 작업이 주말·공휴일에 시작한 비율: 92.2%

## 7. 예측 곡선(E)과 완전 정보(C)의 차이

- 완전 정보 가정을 풀면 절감률이 3.0%p 줄어든다: C(실제 곡선을 미리 안다고 가정) 9.1% → E(전주 같은 요일 같은 시각 값으로 예측) 6.2%.
- 확률과통계 연결: 예측값은 '지난주 같은 요일 같은 시각'이라는 가장 단순한 추정이다. 계절 평균, 이동평균, 일기예보(일사량) 같은 정보를 더하면 차이를 줄일 여지가 있다.

## 8. 에이징 강도(γ) 민감도

γ가 작을수록 일찍 타협해 대기가 짧고, 클수록 깨끗한 시간을 오래 기다린다. γ=inf는 에이징 없이 마감 보호만 둔 경우.

| γ | A 대비 절감률 | 마감 위반 | 평균 완료 지연(h) |
|---|---|---|---|
| 1 | 7.0% | 0 | 24.0 |
| 2 | 8.5% | 0 | 28.9 |
| 3 (기준) | 9.1% | 0 | 30.9 |
| 4 | 9.6% | 0 | 32.0 |
| 6 | 9.9% | 0 | 33.0 |
| inf | 10.0% | 0 | 34.5 |

마감 위반 0건은 에이징이 아니라 15분마다 수행하는 EDF 가능성 검사 덕분이다. 운영체제의 실시간 스케줄링에서 '이 작업들을 모두 마감 안에 끝낼 수 있는가'를 미리 따지는 schedulability test와 같은 개념이다. 에이징 γ는 절감률(과 대기 시간)만 조절한다. 기준값 γ=3는 2025년 데이터로 여러 값을 돌려 본 뒤 중간값으로 골랐다(같은 데이터로 고른 값이라는 점은 한계).

## 11. 가정 목록

1. 작업 세트는 가상이다. 시드 20261116, 30개(당일 18, 익일 6, 주간 6), 실행 시간·전력·메모리 바운드 비율은 `scripts/config_simulation.py`의 범위에서 무작위.
2. 같은 작업 세트가 매일 들어오고, 날짜마다 독립 실험으로 본다(다른 날 작업과 슬롯을 다투지 않음). 주간 작업이 매일 들어오는 것은 실제보다 많다.
3. 서버 동시 실행 슬롯 2개, 작업은 한번 시작하면 끝까지 실행(중단·이동 없음).
4. 스케줄러는 15분마다 대기열을 보고, 탄소 곡선은 1시간 단위 값을 쓴다.
5. 현재 관행(A)은 모든 작업을 새벽 2시에 마감 빠른 순으로 대기열에 넣는다. 2개 슬롯이 다 차면 오전·낮까지 이어서 돈다.
6. C, D는 실제 탄소 곡선을 미리 안다고 가정(완전 정보). E만 전주 같은 요일 값으로 예측.
7. DVFS: 주파수 (1.0, 0.8, 0.6), 동적 전력 ∝ f³(전압이 주파수에 비례), 정적 전력 비율 0.33(민감도 (0.21, 0.5)), 실행 시간은 CPU 바운드 부분만 1/f로 늘어남. 주파수는 마감 안에서 배출(에너지 × 실행 구간 평균 탄소)이 가장 적은 것을 고름.
8. 에너지는 작업이 도는 동안의 전력만 센다. 작업이 없을 때 서버 대기 전력, 냉방 등 데이터센터 부대 전력(PUE)은 넣지 않았다.
9. 에이징 γ=3, 마감 보호는 EDF 가능성 검사(f=1 기준, 빈틈 메우기 없는 보수적 검사).

## 12. 한계

1. 탄소 곡선은 평균 배출계수 기준이다. 작업 하나를 옮겼을 때 실제로 늘고 주는 발전기(한계 발전기)의 탄소와는 다를 수 있다(1단계 한계 2번).
2. 대학 서버 몇 대의 작업 이동은 전력망 전체에 영향을 주지 않는다고 가정했다. 많은 데이터센터가 동시에 한낮으로 몰리면 곡선 자체가 바뀔 수 있다.
3. 작업 세트와 전력 값은 가상이다. 절감률은 '이런 성격의 작업이라면'이라는 조건부 결과다.
4. DVFS 모델은 단순화했다(f³, 정적 비율 고정, 메모리 바운드 비율 고정). 실제 CPU는 전압을 일정 수준 아래로 못 내리고, 주파수 단계도 더 많다.
5. 완전 정보 가정(C, D)은 실제보다 낙관적이다. 예측 오차의 영향은 E로 따로 보였다.
6. 에이징 강도 γ는 같은 2025년 데이터로 보고 골랐다.
