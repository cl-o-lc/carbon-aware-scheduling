# 03. 마감 보호를 EDF 가능성 검사로 한 이유와 에이징의 역할

## 배경

사용자 설계에서 C 정책은 "B(탄소 인지 탐욕) + 에이징, 마감 위반 0건 목표"였다. 에이징과 "최종 시작 가능 시각 N시간 전부터 강제 실행" 여유를 조합해 2025년 349일로 시험했다(저장소에 남기지 않은 임시 탐색 스크립트).
- 여유 1~2시간: 에이징 강도와 관계없이 연간 21~422건 위반이 남았다. 당일 작업들이 같은 한낮을 기다리다 마감 직전에 몰리는데 슬롯은 2개뿐이기 때문이다
- 여유 3시간 + 에이징 강도 γ 3 이상: 이 데이터에서는 0건이었다. 하지만 구조적으로 0건을 보장하지는 않고, 절감률이 8.69~9.02%로 가능성 검사 방식(9.14%)보다 낮았다

탄소만 쫓는 B는 349일 동안 3,400건 위반했다.

(정정: 진행 중 보고에서는 "에이징만으로는 여러 값을 시험해도 연간 수백 건이 남았다"고 했으나, 위와 같이 여유 3시간 조합에서는 0건이 나온 경우도 있었다.)

## 선택지

- 에이징 강도와 강제 실행 여유를 맞춘다(여유 3시간 + γ 3 이상. 이 데이터에서는 0건이지만 보장되지 않고, 절감률이 더 낮음)
- 매 15분마다 EDF 가능성 검사를 한다: "지금 아무것도 시작하지 않아도 남은 작업을 마감 빠른 순(EDF)으로 넣으면 모두 마감 안에 끝나는가"를 확인하고, 안 되면 마감이 급한 작업부터 강제로 시작한다

## 결정

C, D, E, C7에 EDF 가능성 검사를 넣는다. 에이징은 탄소 기준을 얼마나 빨리 넓힐지만 정한다. 기본값은 γ=3이다. 사용자 승인 조건: 요약 문서와 발표에 "마감 위반 0건은 에이징이 아니라 15분마다 수행하는 EDF 가능성 검사 덕분이고, 에이징 γ는 절감률만 조절한다"를 명확히 적는다.

## 이유

- 349일 모든 날에 위반 0건이다. 강제 실행 여유를 맞추는 방식과 달리, 검사를 통과하는 한 남은 작업을 모두 마감 안에 끝낼 일정이 있다는 것이 매 순간 확인된다
- 운영체제 실시간 스케줄링의 schedulability test와 같은 개념이라 전공 연계 설명이 분명하다
- 검사는 f=1 기준이고 빈틈을 메우지 않는 보수적인 방식이라, 통과하면 실제로 실행할 수 있는 일정이 있다
- γ 민감도(1, 2, 3, 4, 6, 없음)에서 절감률은 7.0~10.0%, 위반은 모두 0건이다. γ=3은 같은 2025년 데이터로 고른 중간값이며, 이 점은 한계에 적었다
